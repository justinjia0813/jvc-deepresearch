# S5 自动研究循环

## 来源与改造

Karpathy 的 autoresearch（2026-03-06 发布，github.com/karpathy/autoresearch）让代理反复：改 `train.py` → 固定 5 分钟训练 → 看 `val_bpb` → 变好保留、否则回滚 → 记 `results.tsv`。人只写 `program.md`。它有效的原因是三条约束：**评估器固定且不可改、每轮预算固定、只有变好才保留**。

研究问题没有现成的 `val_bpb`，所以这里先造一个评估器，再套同样的棘轮。

## 1. 选定路径

S4 后可信度最高的假设/方案，或"答案对决策影响最大且不确定性最大"的那一条（看消融的方差贡献）。

## 2. 固定评估器（循环中不得修改）

挑一个与研究问题匹配的分数，写进 `program.md` 并在每条 `loop` 记录的 `evaluator` 字段保持一致：

| 问题类型 | 评估器示例 |
| --- | --- |
| 预测类（价格、时间、规模） | 历史回测误差（MAPE）；或预测区间宽度（P90−P10）在保持校准下越窄越好 |
| 技术路线判断 | 关键 crux 的证据强度分：每个 crux 0–3 分（无/弱/中/强独立证据）求和 |
| 成本/经济模型 | 模型对已知数据点的拟合误差 + 区间宽度 |
| 算法/工程方案 | 基准测试指标（如精度、延迟），固定数据集和种子 |

## 3. 每一轮

1. 列出开放问题与可改动项，估计每项的**价值信息量（VOI）**：如果查清，结论/决策改变的概率 × 影响大小。
2. 选 VOI 最高的一项，提出**一个**改动：一组新检索、一个新实验、改模型的一个假设、换一个数据源。
3. 在固定预算内执行（例：每轮 ≤ 20 条查询或 ≤ 1 个实验或 ≤ 15 分钟）。
4. 用评估器打分，`score_after` 优于 `score_before` 则 `kept: true`，否则丢弃并在 `change` 后写原因。
5. `add loop`。

## 4. 停机（满足任一）

- `plateau`：连续 K 轮（默认 3）无保留；
- `voi`：最高 VOI 已低于下一轮成本；
- `budget`：预算用完；
- `refuted`：出现推翻主结论的结果 → 回到 S3 补一轮辩论，再决定是否重启循环。

最后一条 `loop` 记录写 `stop_reason`。

## 5. 防作弊

- 不得改评估器、阈值或测试数据来"变好"；要改就重开一个循环并在报告里说明。
- 保留的改动要能复现（脚本 + 种子 + 来源 ID）。
- 每 5 轮做一次反向检查：随机抽一个已保留的改动回滚，看分数是否真的依赖它。
